SPOTTY EXPOTTY -- PROJECT SUMMARY
================================================================================

Status: working timeline-scrub prototype (scrub, preview-clip jumble, Spotify
handoff), as of 2026-10-24. See
PROJECT_PROGRESS.md for what's actively being worked on right now, and
CHANGELOG.txt for the full historical log -- this file stays a mid-altitude
snapshot, not a duplicate of either.

--------------------------------------------------------------------------------
OBJECTIVE

An HTML project to visualize, analyze and interpret the owner's Spotify
diary playlists (Exportify CSVs). Which specific views and analyses to build
has not been decided yet.

--------------------------------------------------------------------------------
SCOPE

In scope: the timeline scrub player (scrub through every song-add event in
order, with preview-clip jumble and real-song handoff). Further visualizations
and analyses (audio-feature trends, genres, artists, repeats) are planned but
not chosen yet.

Out of scope / dormant: the non-diary playlists directly in
data/Exportify Export/ (only the Tingo Tango subfolder is loaded).

Audience / how it's used: single-user personal prototype (the playlist
owner), run locally or on Vercel.

--------------------------------------------------------------------------------
CURRENT STATE

Built (2026-10-23/24) and tested in the built-in browser:
- data/processed/timeline.json: 6,345 add events across 42 playlists, 5,450
  (85.9%) with a Deezer clip id. 5,776 unique tracks; 4,939 (85.5%) have an
  exact Deezer-by-ISRC clip, 837 do not (no iTunes fallback used).
- Input (owner's scheme, 2026-10-24): desktop wheel = scrub, click on the timeline
  = jump there, click-drag = zoom with the playhead as origin; touch: one-finger
  drag = scrub, tap = jump, pinch = zoom; arrow keys. Zoom limits are a dev-panel
  range bar (0-100 % log scale, 2 minutes .. whole timeline). Landing in an empty
  stretch plays the last song added before that time. The title is a link to the
  track on Spotify and is cleaned (remaster/live/feat/year decoration removed; 904
  of 5,042 unique titles changed); the album cover (Spotify oEmbed) is the
  play/pause button; the Spotify player is invisible and loops when it ends
  (verified: position reached 29,713 ms, wrapped back and kept playing).
- Timeline visuals: Bar Width slider; Timeline Visual Style dropdown (None, Glow
  Stems, Smooth Density, Feature Line, Mood Ribbon) with per-style settings shown
  only for the selected style; nested toggleable "Album Cover Colors" group (4
  colour modes: stacked per song, average, vivid dominant, palette gradient). Data: 6,295 of 6,341 timeline entries (99.3%) have cover colours
  (5,730 of 5,773 tracks; 4,164 distinct palettes); all four modes were checked by eye on real data.
- Layout: all on-screen elements (title, artist, album line, cover, timeline) are
  registered with the UI Layout Engine with per-device overrides, editable in the
  engine Inspector (dev panel > UI Layout); layout saves with Sync as extra.uiLayout.
  Tested: Inspector edit moved the cover 158 -> 216 px (30vmin of 720), Sync-payload
  round trip restored it, phone (375x812) layout fits.
- Dev-panel Save/Reset go to GitHub through /api/save-settings (ported from
  HANDO); not yet tested end to end on Vercel. The save secret is a client constant (owner's
  instruction, same as HANDO); the GitHub token is server-side only (Vercel env).
- Added 2026-10-24: timeline playlist rows ordered by start date with hover names; toggleable curve
  groups for wheel scrub px per notch (by zoom scale) and for the starting span (by position along the
  timeline); track title never underlined, with a toggleable 6-mode hover/press animation group; a
  Background subgroup with 10 modes (color, multi-stop gradient, cover average / border radial / border
  average / colour-only average, blurred cover, palette gradient, spotlight) that follows the cover live.
  Tested in the built-in browser (see CHANGELOG); not tested on a real phone or on Vercel.
- Clip pool (measured 2026-10-24 as time from play() to the 'playing' event,
  one wheel notch = 1 song): ~3 songs/s -> 9 of 9 songs-with-a-clip made sound
  (median 34 ms, max 94 ms); ~7 songs/s -> 19 of 19 (median 5 ms, max 108 ms);
  ~12 songs/s -> 6 of 37 (16%). 0 failed lookups. (An earlier version counted
  play() calls instead of real sound and over-reported; see CHANGELOG.)
- Spotify embed handoff after scrubbing stops: confirmed the embed switched to
  the right song and played (a 30 s "Preview" because that browser pane wasn't
  logged in to Spotify).
- ~55 dev-panel controls in 7 groups (Scrub Audio, Scrub Preload, Scrub Input,
  Spotify Handoff, Timeline Look with nested Album Cover Colors, UI Layout);
  Mobile twin rows confirmed to appear when "Show in Mobile/Landscape" is checked.
  The scaffold's Component Gallery groups were removed.
Not tested: real phones/touch, Vercel deployment, logged-in full-song playback.

--------------------------------------------------------------------------------
DECISIONS

- Preview clips come from Deezer (by ISRC), not Spotify -- Spotify stopped
  providing preview_url to newer apps (from memory of its 2024 API changes,
  not re-verified), and an embed alone loads too
  slowly (456-948 ms cold) to flick through; preloaded clips start in ~1 ms.
- Save Deezer track ids, never URLs -- links expire in ~14.98 min.
- Handoff to the Spotify embed on stop rather than a Spotify login/SDK -- no
  API key or Premium needed.
- iTunes fallback not used -- its matches are by title/artist (loose,
  unverified) and its rate limit makes a full pass ~1 hour.
- Position and scale of every element belongs to the UI Layout Engine (owner's
  request); the engine excludes typography, so text size is three scale sliders.
- Album cover colours are precomputed offline (Spotify oEmbed + Pillow) because the
  timeline needs the colours of every song in a bar at any zoom.

--------------------------------------------------------------------------------
DATA SOURCES

Exportify CSV exports of the owner's Spotify playlists, in
data/Exportify Export/. The diary playlists are in the Tingo Tango subfolder
(42 files as of 2026-10-23). See CLAUDE.md "Vocabulary" for how the playlists
are made and named. Columns include Track Name, Album Name, Artist Name(s),
Release Date, Added At, Genres, Record Label, and Spotify audio features.

--------------------------------------------------------------------------------
KNOWN LIMITATIONS

- 14.5% of unique songs (837 of 5,776) have no clip; they're silent while scrubbing.
- Above roughly 7 songs/s scrubbing outruns the clip lookups (the proxy serves
  Deezer at ~8 lookups/s to stay under its limit), so most songs are silent
  (16% made sound at ~12 songs/s). Not built: playing the nearest already-loaded
  clip instead (would put the wrong song's audio under the title).
- Preview clips are Deezer's 30 s cut, so the "mid-song" start is within that cut.
- Mobile/touch, Vercel deploy and full-song (logged-in) playback are untested.
- Deezer's terms for this use weren't checked.
- Data oddities not investigated: a song in Junior.csv dated 2026-11-10;
  Treinta.Cero_(2).csv looks like a copy of Treinta._Cero.
- data/processed/timeline.json is generated from a lookup output kept outside
  the repo; re-running the lookup is needed to regenerate it.
